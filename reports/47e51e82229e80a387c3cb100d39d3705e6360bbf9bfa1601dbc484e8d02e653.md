# Analysis of LOTUSLITE sample

Ire's full analysis output for sample [`47e51e82229e80a387c3cb100d39d3705e6360bbf9bfa1601dbc484e8d02e653`](https://www.virustotal.com/gui/file/47e51e82229e80a387c3cb100d39d3705e6360bbf9bfa1601dbc484e8d02e653), rendered as markdown.

Section labels, function references, and bullet structure are all from Ire.

**Label:** `malicious`

## Summary

Malicious Windows RAT/backdoor/dropper. It installs as `C:\ProgramData\SmartPrint\SmartPrintScreen.exe`, persists through `HKCU\...\Run\DadaBank` with `--DaDaBar`, shows a fake corrupted-PDF error, communicates over HTTPS with a custom C2 protocol using magic `3001798623`, supports remote `cmd.exe` shell execution, directory listing, file creation/truncation/append, and chunked data upload. It uses XOR/reversal string obfuscation, manual export resolution, misleading SmartPrint/PDF/banking/QR/NFAPI-themed names, and decoy exports.

## Evidence

The binary contains multiple strong indicators of intentional malicious functionality. Persistence is implemented by a misleadingly named function, `nfapi::nf_unRegisterDriver`, which writes a user Run-key value under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` with value name `DadaBank` and data `"C:\ProgramData\SmartPrint\SmartPrintScreen.exe" --DaDaBar`. Installation logic in `sub_10002d37` creates or uses `C:\ProgramData\SmartPrint\`, copies the current executable to `C:\ProgramData\SmartPrint\SmartPrintScreen.exe`, handles an `AMPV.dll` component, invokes the persistence routine, and displays a decoy error message: `Error: The Pdf file is corrupted. Please restart your computer and try again, or contact the original author.` The dispatcher `sub_10002fb9` compares the current execution path with the intended install path and either installs the malware or, when launched from the installed path with marker `--DaDaBar`, starts the backdoor command loop.

Network command-and-control behavior is centered in `sub_100021e3` and `sub_10002709`. The sample contains C2-related configuration strings including `forms.microsoft.com`, `/info/faq/v6`, `https://www.google.com/`, `JSESSIONID=x-ms-cpim-geo`, and a fake Chrome-like user agent string. Communication is performed over HTTPS/port 443 using dynamically resolved WinHTTP-style APIs. The C2 protocol uses a custom packet format with DWORD magic value `3001798623`, followed by a command/type field, payload length, and payload bytes. `sub_100020b8` builds these packets, while `sub_10002709` sends an initial beacon and dispatches received commands.

The command dispatcher supports direct backdoor capabilities. Command ID `10` starts an interactive `cmd.exe` session through pipes using `sub_100018b0`; command ID `1` writes attacker-provided C2 payload data to shell stdin via `sub_10001b2d`; `sub_10001804` reads command output from the shell pipe into an internal buffer; `sub_10001bbc` retrieves buffered shell output for exfiltration; and command ID `11` stops the shell using `sub_10001a96`. Filesystem control is also present: command ID `3` invokes directory listing logic in `sub_10001db4`, command ID `13` creates or truncates files, and command ID `14` appends or writes data through `sub_10002169`. Upload or response data is chunked by `sub_10002639` into blocks of up to `0x10000` bytes and sent back to the C2.

The sample uses obfuscation and stealth techniques. `sub_100011d0` decodes hidden strings/API names using XOR with a five-byte key and reversal. `sub_10001241` manually walks PE export tables to resolve functions by name. `sub_100012de` combines string decoding with export lookup, and `sub_10001324` decodes DLL/module names and dynamically loads or obtains modules. This reduces static import visibility and conceals strings such as API names, paths, commands, and configuration material.

Additional suspicious artifacts include global configuration initializers for `C:\ProgramData\SmartPrint`, `SmartPrintScreen.exe`, `BelievemeIamMustang-Panda`, `--DaDaBar`, `/info/faq/v6`, `forms.microsoft.com`, `https://www.google.com/`, `JSESSIONID=x-ms-cpim-geo`, and a Chrome-like user agent. The binary exports or defines numerous decoy banking/QR-themed names, including `Query_Bank`, `NextBank_BMI`, `BankSepah_Iran`, `BankToman_BMI`, `QRTAPI_GetLastError`, `BankInitialize`, `JpgSymbolToBMP`, `qrBankAddData`, `BankofChina`, `BankChina`, `qrBankFinalize`, and `qrBankInit`; many only show message boxes or terminate the process. These decoy exports are inconsistent with the observed SmartPrint/PDF installation behavior and RAT functionality. Repeated `nfapi::nf_registerDriver` references and NetFilter-style naming are also suspicious in the context of a persistent C2 backdoor, although the analyzed snippets do not conclusively prove active packet interception or driver installation beyond the Run-key persistence routine.

## Detailed report

The executable is a persistent Windows RAT/backdoor/dropper disguised as a SmartPrint/PDF-related component.

Core execution flow:
- `sub_10002fb9` acts as the main install-or-run dispatcher.
- If the binary is not running from its intended installed location, it invokes `sub_10002d37` to install itself.
- The install path is `C:\ProgramData\SmartPrint\`.
- The installed executable name is `SmartPrintScreen.exe`.
- The autostart command uses the marker argument `--DaDaBar`.
- If already installed and invoked with the expected marker, the dispatcher sets up the working environment and enters the RAT loop in `sub_10002709`.

Persistence and installation:
- `sub_10002d37` creates or uses `C:\ProgramData\SmartPrint\`.
- It copies the current executable to `C:\ProgramData\SmartPrint\SmartPrintScreen.exe`.
- It references or handles `AMPV.dll`.
- It invokes `nfapi::nf_unRegisterDriver`, despite the misleading name.
- `nfapi::nf_unRegisterDriver` writes the Run key:
  - Key: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  - Value: `DadaBank`
  - Data: `"C:\ProgramData\SmartPrint\SmartPrintScreen.exe" --DaDaBar`
- The installer displays a fake decoy PDF-corruption message to the user, indicating intentional social-engineering camouflage.

C2 communication:
- `sub_10002709` implements the main infinite C2 command loop.
- `sub_100021e3` performs HTTPS C2 request/response behavior over port 443 using dynamically resolved WinHTTP-style APIs.
- Embedded C2/configuration strings include:
  - `forms.microsoft.com`
  - `/info/faq/v6`
  - `https://www.google.com/`
  - `JSESSIONID=x-ms-cpim-geo`
  - `Mozilla / 5.0 (Windows NT 10.0; Win64; x64) AppleWebKit / 537.36 (KHTML, like Gecko) Chrome / 147.0.7727.102 Safari / 537.36`
- The traffic is structured as a custom binary protocol with magic value `3001798623`.
- Packet layout is: magic DWORD, command/type DWORD, payload length DWORD, then payload bytes.
- `sub_100020b8` builds C2 packets.

Backdoor commands:
- Command ID `1`: sends received payload data to an active shell stdin pipe.
- Command ID `3`: performs directory listing.
- Command ID `6`: resets/re-beacons state.
- Command ID `10`: starts an interactive `cmd.exe` shell.
- Command ID `11`: stops the active shell.
- Command ID `13`: creates or truncates a file.
- Command ID `14`: appends or writes file data.
- Command ID `15`: sends an `O-K` acknowledgement.

Remote shell capability:
- `sub_100018b0` creates stdin/stdout pipes and launches `cmd.exe` with inherited handles.
- A worker thread or scheduler task reads shell output.
- `sub_10001804` repeatedly reads shell output through `ReadFile` and buffers the result.
- `sub_10001b2d` writes C2-provided command data to shell stdin, adding line termination as needed.
- `sub_10001bbc` retrieves buffered shell output so it can be exfiltrated.
- `sub_10001a96` stops the shell and cleans process, pipe, and buffer state.
- This provides remote command execution.

Filesystem capability:
- `sub_10001db4` lists directories using `FindFirstFileA` and `FindNextFileA`.
- If no path is supplied, it defaults to `C:\`.
- Directory output is formatted with entries resembling `filename|DIR|size` or `filename|FILE|size`.
- `sub_10002169` writes attacker-provided data to files in truncate/write mode (`wb`) or append mode (`ab`).
- The file writer retries several times with short sleeps between attempts.
- `sub_10002639` uploads generated or local data to the C2 in chunks of up to `0x10000` bytes.

Obfuscation and dynamic API resolution:
- `sub_100011d0` decodes hidden strings using XOR and reversal.
- `sub_10001241` manually walks a module PE export table to find functions by name.
- `sub_100012de` decodes API names and resolves them manually.
- `sub_10001324` decodes DLL/module names and dynamically obtains or loads modules.
- This hides API usage and string indicators from ordinary static import/string inspection.

Decoy and camouflage indicators:
- The sample uses SmartPrint and PDF-corruption themes to disguise installation.
- It contains the marker string `BelievemeIamMustang-Panda`.
- It contains many banking and QR-themed export/function names that largely show message boxes or exit, including `Query_Bank`, `NextBank_BMI`, `BankSepah_Iran`, `BankToman_BMI`, `Relevant_people`, `Bank_Relevant_people`, `QRTAPI_GetLastError`, `Riyal_Uninitialize`, `Riyal_I_CleanupRepository`, `BankInitialize`, `JpgSymbolToBMP`, `qrBankAddData`, `BankofChina`, `BankChina`, `qrBankFinalize`, and `qrBankInit`.
- These exports are inconsistent with the observed RAT behavior and appear to be camouflage or misdirection.

Runtime/support code:
- A large portion of the binary consists of MSVC CRT, C++ runtime, exception handling, file I/O, memory, threading, synchronization, Concurrency Runtime, ETW/tracing, and COM/WinRT support code.
- These routines support the malware’s execution, threading, shell-output reading, and C2 task handling but are mostly compiler/runtime library code rather than primary malicious logic.

The verified behaviors (self-installation into ProgramData, Run-key persistence, decoy error presentation, obfuscated API/string resolution, HTTPS C2, custom command protocol, remote `cmd.exe` execution, directory enumeration, file writing, and chunked exfiltration) are sufficient to classify the binary as malicious.
